# ShapeChange Shader

VRChat のアバターを、箱・球・円柱・平面など 16 種類の形へ変形するシェーダーと、そのセットアップ用の Unity Editor ツール。Unity 2022.3.22f1 / Built-in Render Pipeline / lilToon 2.4.1 / PC 版 VRChat（Windows・DX11）で確かめている。

モデルやテクスチャは含まない。手持ちのアバターを複製して変形用のデータを作るので、元のアバター、FBX、マテリアルは変更しない。

## 導入

VCC または ALCOM に次のリポジトリを追加し、プロジェクトに「ShapeChange Shader」を入れる。

```text
https://radiann-kswg.github.io/VRCShader_ShapeChange/index.json
```

- [VCC / ALCOM に追加する](https://radiann-kswg.github.io/VRCShader_ShapeChange/)（上の URL を登録するページ）
- VPM CLI: `vpm add repo https://radiann-kswg.github.io/VRCShader_ShapeChange/index.json`

Standard の Opaque 素材だけなら、このパッケージだけで準備できる。lilToon 素材を使うアバターでは lilToon も入れる（確かめた版は 2.4.1）。lilToon を後から入れた場合は、このパッケージのフォルダーを右クリックして Reimport する。

## 使用方法

1. アバターをTポーズにして `Tools > ShapeChange > Setup Avatar` を開く。
2. Hierarchyで対象を選ぶか、Humanoid Animatorを直接指定する。形状を保つアクセサリーのチェックを外すと、装着位置に追従する。素材・未使用UV・Rigの問題はセットアップ欄に表示される。
3. `複製してセットアップ` を押す。元のアバター、FBX、マテリアルは変更しない。
4. `操作する複製` で形状を選び、「変形（On / Off）」を切り替える。Offは元の外観、Onは完成形。厚みや四肢の設定は対応する形状に表示される。

`BodyEar`・`Body_Ears`（つけ耳）・`BodyTail`・`Body_Tail`（つけ尻尾）もアクセサリーとして初期判定する。チェックを外すと形状保持、チェックを入れると箱・球などの外形へ統合する。統合時には顔・前後中央の保持から外し、元の耳や尻尾が外側へ残らないようにする。部位の選択を変えるときは、その選択で `複製してセットアップ` を実行する。

`Assets/ShapeChangeShader/Shaders/Generated` 以下に専用のPrefab、メッシュ、マテリアル、外観画像、Previewシーン、17個の形状Clip（元姿を含む）と8組の姿勢Clip（Humanoid + FX、平面向けを含む）、腕・脚のモーフ端点Clipを各2本生成する。セットアップをやり直すと別フォルダーになる。以前の複製は「追加形状を含むShape Clipを更新」で形状Clipを追加できる。

| 番号 | 形状 |
|---|---|
| 0 / 1 / 2 | 立方体 / 直方体 / 頭付き立方体 |
| 3 / 4 / 5 | 膨体 / 真球 / 頭付き2.5頭身球体 |
| 6 / 7 / 8 | 身長方向円柱・顔上面 / 同・顔側面 / コイン |
| 9 / 10 | 人型平面・水平回転 / 人型平面・奥行圧縮 |
| 11 / 12 | 人型平面・細幅 / 人型平面・板幅 |
| 13 | 縦平面化・頭上から足元へ圧縮 |
| 14 / 15 | 長方形の板・紙 / 長方形の反物 |

腕・脚はそれぞれ `残す / 胴体へ収納 / 非表示` を選べる。膨体（形状3）の収納は、四肢を短い突き出しとして残す。形状保持のアクセサリーは、装着先の表面に置いた基準点を追従し、表面の向きと装着先の均等倍率を適用する。元のボーンウェイト、ボーン参照、BlendShapeを維持し、接点の骨移動には身体と共通の式を使う。装飾の相対位置には均等倍率と回転を使い、接点の移動と分けて処理する。`アクセサリーを装着先の倍率へ合わせる` と `アクセサリー倍率の補正` で素材ごとに調整できる。非表示にした四肢に属するアクセサリーも非表示になる。

以前のセットアップ済みアバターには `既存の複製へアクセサリー追従を適用`、または `Tools > ShapeChange > Update Accessory Following` を実行する。未処理だったアクセサリーの専用メッシュ・素材、Prefab、Previewシーン、AnimationClipを更新する。元のアバターは変更しない。

表情などがアニメーションから素材を差し替える場合も、専用Controller・Clip・素材を生成して変形設定を引き継ぐ。元の表情色や画像を保ち、操作時は差し替え先の素材にも同じ変形値を設定する。現在は保存済みの通常Controllerと外部 `.anim` にあるSkinnedMeshRenderer素材差し替えに対応する。該当するOverride Controller、FBX内Clipや未対応の外部グラフは停止して知らせる。既存の専用素材への手修正は、更新時に差し替え元の表情素材から再生成される。

既存の複製を今回の方式へ更新する場合は `倍率・姿勢を更新してポーズClipを保存`、または `Tools > ShapeChange > Upgrade Posture and Scale` を実行する。アクセサリーの座標・法線を再生成し、専用アセットを更新する。

装着基準点は胴体・左右の腕・左右の脚・左右のつけ耳の最大7群。`BodyEar` は左右を分け、耳・尻尾はウェイトを持つ該当ボーンの付け根を基準にする。装着先の三角形へ最近点を取り、重心座標で部位マスクと法線を補間する。途中段階も装着先と同じ変形から接触面の向きを求める。同じ群に属する無関係な装飾を一つのRendererへまとめる場合は、事前に分ける。複雑に重なる装飾や大きなPhysBone変位では個別調整が必要。元のメッシュ同士の接触を厳密に解く処理ではない。

`顔の縦横比・前後中央の形を保持` が既定でオン。箱・真球（形状0/1/2/4/5）は、つけ耳を除く **頭頂〜顎下の高さが形状基準高の1/2.5（40%）** になる基準倍率を使う（面投影の奥行きは別処理）。膨体（形状3）は元の顔の正面XYの大きさを保ち、球の上前方へ頭を沈める（全体サイズの倍率には追従）。膨らみ1では胴の幅・高さ・奥行きが等しく、値を変えると横・奥行きが増減する。頭部メッシュと顔の前方中央から頭頂・顎下を測る。これは正面の画素面積40%ではなく高さ比で、耳や残した脚の張り出しは基準高に含めない。円柱・コインでは従来の正面投影面積による占有率を使用する。形状9〜12は全身共通の薄型化を優先する。

首周りはメッシュ共通の位置マスクで元の襟・皮膚の接続を保持し、その外側を胴体へなじませる。頭部に追従する範囲で頂点の接続・UVを保つ。投影対象では正面XYの対応を保持し、奥行きは共通の投影へ含める。襟の外縁まで完全な等長変形にする拘束ではない。顔の自動計測にはアバターに指定済みの表情用メッシュを優先し、メッシュ名への依存を取り除いた。襟や長い髪の重なりは別途目視する。以前の複製は `倍率・姿勢を更新してポーズClipを保存` を実行して頭部計測を更新する。

直立の頭付き立方体・頭付き球体は、胴体の箱・球そのものを基準高の下側60%へ収め、上側40%に元メッシュの頭を置く。胴体を全高まで伸ばして頭・襟を覆ってしまう状態を避け、箱・球の胴体は縦横比も保つ。鎮座用の関節配置とアクセサリーの倍率もこの胴体寸法を使う。

腕・脚を「残す」にすると、それぞれ `変形・収納` を0〜1で操作できる。0は元の太さ、途中は胴体の大きさに合わせて膨らみながら収納し、1は「胴体へ収納」と同じ頂点位置・表示範囲になる。膨体だけは0から短縮へ移り、1で全体サイズに対して長さを元の1/4、太さを0.7倍にした短い四肢を残す。「非表示」は従来通り別設定。脚の収納量は接地用の全身の持ち上げ量にも反映する。アクセサリーも装着点の同じ変形・倍率へ追従する。

手首・足首等に属する形状保持アクセサリーは、収納モーフ0.7〜1で一緒に非表示へ移り、完全収納後の腕輪等が空中へ残ることを防ぐ。頭・胴体側のアクセサリーは表示を保つ。膨体の短い四肢に属する装飾は、四肢の太さを基準にした均等倍率で表示する。顔・襟の周囲は閉じた補助面を奥へ下げ、元メッシュの表示切替を外縁の狭い帯へ限定する。

顔の目・口・輪郭は同じ面内倍率にし、個別に横へ引き伸ばさない。直立・顔保持・凹凸圧縮オンの形状0/1/3/4/7は、箱の前面、球・円柱の前方曲面へ奥行きを投影する。`衣装の重なり保持` に応じた正の奥行き倍率（0.13〜0.35）を残し、目・まつげ・髪の前後順序を保つ。形状6は頭の奥行きを浅くして円柱の長さ方向の先端へ置き、顔のXYを端面XZへ回す。形状8は顔を円盤の前面へ置き、厚みに応じて頭の奥行きをさらに圧縮する。6/8は端面寸法で頭の均等倍率にも上限を設ける。表情・骨の変位と頭部法線にも同じ投影を使う。頭頂〜顎下の40%は正面高さの比率で、投影後の3D辺長・面積の一定性を意味しない。頭付き形状や凹凸圧縮オフでは従来の頭部保持を使う。頭・首の接続部分と首より下の長い髪には滑らかな遷移を入れる。

`凹凸を減らして外形へなじませる` が既定でオン。顔保持オンの箱・球・顔側面円柱では、首から下の上下順序を保つ断面変形を使う。アーマチュアから測った胴体幅・奥行きを基準とし、断面内の半径を単調に圧縮する。襟から裾へ向かう順序と衣装の厚みを残し、上部で頭の基準倍率と面投影へ接続する。それ以外の立体モードは共通楕円体による変形を使う。`衣装の重なり保持` を下げるほど凹凸が小さくなる。顔・四肢との部位マスクの遷移を含む全体の自己交差を保証するものではない。

形状9〜12の平面化は、人型輪郭を残し、スキニング後の全身を共通の薄い奥行きへ投影する。元の奥行きが大きい箇所ほど凹凸を均し、顔・髪・衣装の前後順を保つ。形状9だけ水平へ回転し、11は幅を52%、12は幅を115%にする。矩形の外周へは集約しない。表裏が重ならない小さな厚みを残し、閉じた補助面は使用しない。平面では形状保持の装飾も同じ投影へ含め、現在の骨姿勢で一致する接点を維持する。立体モードの顔の均等拡大・四肢収納・装飾の均等倍率とは別の挙動になる。ファーの追加描画も形状9以上では長さを抑える。

形状9〜15をEditorで選ぶと腕を体側へ下ろす姿勢にする。「平面向けに腕を体側へ下ろす」で再適用できる。14/15はこの姿勢の表裏と各高さの輪郭幅を使い、頭・胴・脚を矩形の左右へ広げる。極端に細い先端は横倍率に上限を設ける。板・反物の外観データがまだない複製や、服・表情を更新した複製は「現在の服・表情で外観を再焼き込み」を使う。衣装や脚の隙間は閉じた補助メッシュで覆い、周囲の色で補う。

この設定をオフにすると、従来の前後中央を均等倍率で保持する方式になる。外周は `胴体外周の形状への追従` で調整（既定0.12）。凹凸圧縮・均等保持ともに、全三角形の面積を一定にする拘束ソルバーではない。元からある交差・開口部や、顔と四肢の張り出しも残り得る。

値をマテリアルから直接変更する場合は補助メッシュを含むすべてのShapeChangeマテリアルを同じ値にする。頭なし形状で保持をオフにすると顔も全面投影され、`顔の下端（焼き込み）` が使える。頭付き形状では頭の形を残す。

## 穴・継ぎ目への対策と制約

元の頂点だけの移動では、左右の脚の間・衣装の開口部を塞ぐ面は作れない。そのため既定では、Unityでアバターを周囲から描画して外観を焼き込み、閉じた補助メッシュを生成する。板・反物と、直立・顔保持・凹凸圧縮を有効にした立体は、不透明な補助面を内側から広げて外形を引き継ぐ。その他の立体設定はディザで切り替える。保持がオンのとき顔は元メッシュを残し、凹凸圧縮がオフの場合のみ胴体の前後中央も保持する。顔の後ろには滑らかな窪みを作り、境界の色を補間する。箱の角・円柱の縁には、急な折れを防ぐ小さな丸みがある。補助メッシュは16,384三角形。

- 焼き込み部分はセットアップ時の服・表情。立体用の外観は複製素材で照明・影・反射を外して色を焼き込み、完成形の法線で陰影を付ける。元の素材は復元する。着替え後は `現在の服・表情で外観を再焼き込み` を実行する。保持オンの顔は元メッシュのBlendShapeとスキニングの変位を倍率付きで反映する。保持をオフにした全身形状の顔は画像になり、リップシンク・瞬きは追従しない。板・反物の表裏画像は従来の正面・背面撮影方式。
- 途中の変形、頭の境界、残した四肢、アクセサリーの装着位置、PhysBoneとの組み合わせは個別調整が必要。任意アバターの無破綻を保証するものではない。
- 外観の焼き込みが不要なら `閉じた補助メッシュで隙間を防ぐ` を外す。この場合、元のメッシュ密度・開口部が結果に残る。
- UV5〜UV8（APIのchannel 4〜7）を専用データに使用する。既存データがある場合は停止し、上書きを明示した場合だけ複製側で使用する。
- 準備したRendererはアバタールートをrootBoneにする。Boundsを広げ、カメラ外でもスキニングを更新するため、追加コストがある。
- 複製側のAvatar Optimizer `Trace And Optimize` は削除する。他の最適化ツールによるUV削除、rootBone変更、メッシュ結合も無効にする。
- StandardのOpaque（Albedo・Normal・Metallic/Smoothness・Occlusion・Emission）、通常版lilToonのOpaque / Cutout / Transparentと輪郭線、lilToon 2.4.1の `Hidden/lilToonFurTwoPass` に対応。Standardの透明・カットアウト、他のFur形式、Lite / Multi / Gem / Refraction / Tessellationやその他の独自シェーダーは未対応。
- Android/Questアバターでは独自シェーダーを使用できない。UnityのプレビューはDX11で動くが、アップロード先はWindowsにする。

## VRChatのAnimator

セットアップ済みの複製を選び、使用する形状を表示して「現在の形状の On / Off Controller を作成」を実行すると、`ShapeToggle_XX.controller` を保存する。操作パラメータは `ShapeChange`（Bool、初期値Off）。OffとOnで同じ形状番号を使い、変形量を0と1の間で0.25秒かけて補間する。

アバターでは生成したステートと遷移をFXへ組み込み、Expression Parametersに `ShapeChange` をBoolで追加する。Expressions Menuに同名パラメータを操作するToggleを設定する。既存のFX・Expressionsはセットアップ時の設定を確認してから統合する。

平面向けは `Pose_Plane.anim` をActionレイヤー等へ、`Pose_Plane_FX.anim` をFXへ同時に組み込む。材質だけを変えても骨姿勢は変わらない。古い複製の姿勢Clipは「倍率・姿勢を更新してポーズClipを保存」で追加できる。既存ControllerやExpressions Menuへの組み込みは手動。

生成した `Original.anim` / `Shape_00.anim`〜`Shape_15.anim` をFXレイヤーに組み込む。既存FXやExpressions Menuは自動変更しない。複製をアバターのルートとして使用する。マテリアルパラメーターは全対象Renderer（補助メッシュと形状保持アクセサリーを含む）に同期させる。

鎮座は `Pose_Seated_00.anim`〜`Pose_Seated_05.anim` のうち選択形状と同じ番号をActionレイヤー等へ置き、対応する `_FX.anim` をFX側で同時に再生する。元姿勢へ戻す組は `Pose_Original.anim` / `Pose_Original_FX.anim`。Actionの有効化にはPlayable Layer Control等によるレイヤーウェイトの設定も必要。ボーン長・スケールを変えず、腕と脚のHumanoid muscleだけを記録する。手を腹へ、脚を前へ向けるポーズ（膨体の短い腕は胴の外へ向ける）で、既存の歩行・トラッキングとの遷移はアバター側で組み込む。Unityでの姿勢確認は実施するが、VRChat内の動作は別途確認すること。

主な値: `_SCAmount` 0〜1、`_SCMode` 0〜15、`_SCArms` / `_SCLegs` 0=残す・1=収納（膨体は短い四肢）・2=非表示。形状番号は整数で変更し、別の形状へ移る場合は一度Amountを0へ戻す。マテリアル差し替えAnimationが既存FXにある場合は生成したマテリアルへ参照を直す。

`Morph_Arms_0.anim` / `Morph_Arms_1.anim` と `Morph_Legs_0.anim` / `Morph_Legs_1.anim` を、それぞれFXの1D Blend Treeの0・1へ設定すると、腕・脚を独立したFloatパラメーターで収納できる。各Clipは該当四肢を「残す」に設定し、`_SCArmMorph` / `_SCLegMorph` のみ操作する。姿勢用の `_FX.anim` にも同じプロパティがあるため、同時使用時はモーフ用レイヤーを後段へ置く等、競合を調整する。Expressions Menu・既存Animatorへの組み込みは手動。膨体の新しい鎮座ポーズを使う場合は、専用複製のポーズClipを更新する。既存の生成済みClipはシェーダー更新だけでは書き換わらない。

## ワールド内の形状変化ギミック

1. ワールドで使用できるHumanoidモデルを `Setup Avatar` で準備し、生成されたPrefabをワールドシーンに置く。Clipのバインド先を保つため、Animatorを準備済みPrefabのルートに置く。
2. 目的の形状の `ShapeToggle_XX.controller` をルートのAnimatorへ設定する。ワールド側のイベントから `ShapeChange` のBoolを操作する。平面向けの骨姿勢が必要なら `Pose_Plane.anim` も同じ操作で適用する。
3. 別の形状に切り替える構成では、Offへ戻ってから次の形状番号を使用する。素材の変形量は取得したClipを使って全対象Rendererに同期させる。

変形は描画に適用される。ギミックの当たり判定や複数プレイヤー間の同期は、必要に応じてワールド側で設定する。

## 検証

`Tools > ShapeChange > Validate and Render Preview` を実行。GPU上の座標・法線・変形量0の不変性、UVデータ、13形状の描画、実メッシュの保護領域の面積と顔の対応を確認する。面投影対象は顔の面内（形状6はXZ、その他はXY）の均等倍率と正の奥行き、その他の頭部は3Dの均等倍率を検査する。709項目の頭部小回帰には、側面円柱で補助面が顔を隠さないことも含む。全16モード・5段階・3模擬姿勢・頭/腕/脚の720条件では、UV接線が実変形面の方向に合うことを確認する。共通の変形場は26方向・5半径・4段階の変形量で、局所的な向きが反転しないことをGPUで確認する。顔・四肢の保持境界や、すべての三角形同士の衝突を検証するものではない。保存先はプロジェクト直下の `Outputs/ShapeChangeValidation` とし、Unityによる画像インポートと出力書込みの競合を避ける。`validation.txt`、`surface-area.csv`、`contact-sheet.png`、`cube-front.png`、`sphere-front.png` を更新する。画像番号00は元、01〜13は形状0〜12、14は中間変形、15は四肢非表示。

参考: [lilToon](https://github.com/lilxyzw/lilToon)、[Unity BakeMesh](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/SkinnedMeshRenderer.BakeMesh.html)、[VRChat Androidの制限](https://creators.vrchat.com/platforms/android/quest-content-limitations/)。

## 開発用リポジトリからの更新

シェーダーとツールは、非公開の開発用リポジトリ `VRCShader_ShapeChange-Develop`（Unity プロジェクト）で調整している。このリポジトリには、開発側の配布リスト（`Tools > ShapeChange > Export Shader Only` の明示リスト）にあるファイルだけを、次のスクリプトで写す。アバターのモデル、モデルから作った生成物、開発用の記録は写さない。

```sh
py .github/scripts/sync_from_dev.py <開発用リポジトリのルート>
```

`package.json` の `version` を上げて `main` へ push すると、[Release ワークフロー](.github/workflows/release.yml) がリリースの zip を作り、VPM のリスティングを更新する。
